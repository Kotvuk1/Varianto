# Roadmap — Trading Lab

Версия: 0.3 (2026-11-04). Даты не указаны: фиксируются только последовательность и критерии перехода. Детали требований: `docs/PRD.md`. Переход к следующему этапу выполняется после того, как пользователь слил PR предыдущей вехи в `main`.

## MVP

Статус на 2026-11-04: M0–M8 выполнены в облачном контейнере (проверки: `docs/PROJECT_STATUS.md`). Не закрыты и зависят от пользователя: живые данные Binance с его устройства, Supabase/Google OAuth/Vercel, проверка на телефоне, приёмка MVP. Открытые дефекты: `docs/KNOWN_ISSUES.md`.

Каждая веха заканчивается PR. Vercel подключается ближе к концу: до этого результат подтверждается скриншотами/видео Playwright на реальных архивных данных (с подписью источника), после — превью Vercel. Подробности: PRD, раздел 11; тестирование и критерии «готово»: `docs/TESTING_STRATEGY.md`.

## v1.1 — Fibonacci Playground и Premium/Discount

Статус: не начато (0%).

Вход: MVP принят; проведено отдельное интервью по Fibonacci.

Содержание: инструмент Fibonacci на слое разметки, задания на уровни и зоны, Premium/Discount относительно диапазона структуры, проверка детерминированным алгоритмом, разбор из шести частей, учёт в прогрессе.

Критерий перехода к v1.2: задания Fibonacci и Premium/Discount проходят тесты на реальных данных; навыки отображаются в «Слабых местах»; пользователь принял PR.

## v2

Статус: не начато (0%), в том числе «Спросить ИИ». Отложено после MVP также: пересмотр PA 11.4 «против HTF никогда не значимо».

Вход: v1.2 принят.

| Направление | Критерий готовности |
|---|---|
| Кнопка «Спросить ИИ» (Claude API) | ИИ получает только факты, проверенные детерминированным алгоритмом; ответ ИИ не влияет на оценку правильности; ключ API хранится только в окружении сервера |
| Inducement | Правило формализовано, покрыто тестами на реальных данных, добавлено в разбор и прогресс |
| Мультипользовательский режим | Данные и RLS проверены для нескольких пользователей; проверка ответов выполняется на сервере (OQ-04 решён, R-08 снят архитектурой); проверена изоляция данных нескольких пользователей |
| VPS (при необходимости) | Включается только если бесплатные тарифы или гео-ограничения Binance блокируют нужную функцию; решение фиксируется в ADR |

## Правила корректировки

- Содержание вех меняется только через обновление PRD и, при архитектурных последствиях, через ADR в `docs/DECISIONS/`.
- Порядок вех M0–M8 можно менять только с подтверждения пользователя.
- Решения пользователя по OQ фиксируются в PRD, раздел 12 (статус и решение).
