# ADR-0002: Lightweight Charts v5 + собственный слой разметки на Series Primitives

Статус: принято (2026-11-03), выбор подтверждён пользователем. Источник: `docs/ARCHITECTURE.md` C6, §2, §8; `INTERVIEW_SUMMARY.md` §6.

## Контекст
- Нужны: свечи + объём, синий/оранжевый стиль и монохром, тёмная/светлая тема, плавный touch-зум и прокрутка на среднем телефоне (NFR-PERF-01).
- Нужна разметка (swing, BOS/CHoCH, OB, FVG, уровни, SL/TP) с привязкой к (время, цена), а не к пикселям; перемещение и удаление касанием; область касания не меньше 44x44 px (FR-DRAW-*).
- Модель разметки (`Mark`, `ARCHITECTURE.md` §4.2) принадлежит нам: её читает и пишет алгоритм, она сохраняется в БД. Библиотека графика не должна определять формат хранения.
- Lightweight Charts (LWC) не умеет рисовать и сохранять объекты (C6, R-03).

## Решение
- График: TradingView Lightweight Charts v5.
- Слой разметки пишем сами в `apps/web/src/chart/`: `DrawingLayer` на Series Primitives (рендеринг поверх серии), хит-тест и ручки на Pointer Events (единый код для касания и мыши).
- Источник истины — массив `Mark[]` в состоянии приложения (zustand); примитивы только рисуют видимое и конвертируют (time, price) <-> пиксели через API шкал LWC.
- Примитивы рисуют только объекты в видимой области; лимит числа объектов; профилирование на M8.
- Версия LWC фиксируется точной; перед M1 проверить актуальность API Series Primitives на выбранной версии (OQ-03 в PRD).

## Рассмотренные альтернативы
| Вариант | Сильные стороны | Почему не выбран |
|---|---|---|
| KLineChart | Встроенные инструменты рисования | Формат и поведение оверлеев задаёт библиотека; каждое нестандартное требование (BOS/CHoCH, OB с привязкой к алгоритму, 44 px ручки, сохранение в нашей модели) всё равно требует собственного кода поверх; меньше контроля над производительностью. |
| Highcharts Stock | Аннотации, зрелая экосистема | Лицензионные ограничения для коммерческого использования (проверить условия, если проект станет коммерческим); тяжёлый бандл для мобильного; аннотации — не наша модель разметки. |
| TradingView Advanced Charts | Полный набор инструментов рисования | Требует отдельного доступа/лицензионного соглашения и размещения библиотеки (проверить условия); сохранение и API разметки заданы библиотекой, нашу модель `Mark` пришлось бы конвертировать; избыточно (много индикаторов, нам нужен только объём). |

## Последствия
- Плюс: полный контроль над моделью разметки, хит-тестом, формой меток (форма и подпись, а не только цвет — FR-DRAW-15) и производительностью.
- Плюс: `Mark` не зависит от библиотеки; замена графика не затрагивает хранение и алгоритмы.
- Минус: инструменты, хит-тест, перемещение и касания пишем сами (веха M1 — самая рискованная по UI).
- Минус: нужна атрибуция TradingView по условиям лицензии LWC (проверить текст лицензии на M1).
- Требование к реализации: преобразование (time, price) -> пиксели должно корректно работать для времени между свечами и справа от последней свечи.
