# ADR-0008: Local-first хранилище за интерфейсом Repository; Supabase в M7

Статус: принято (2026-11-03). Источник: `ARCHITECTURE.md` C4, §5.4, §6; решения пользователя: авторизация в конце (M7), до этого IndexedDB; гостевой режим отложен.

## Контекст
- Авторизация и Supabase появляются в M7; до этого модули M3-M6 должны сохранять попытки, разметку терминала и настройки (FR-PROG-10, FR-TERM-04).
- Модель данных сразу многопользовательская (FR-AUTH-05), но выбор и переключение хранилища не должны переписывать UI.
- Supabase Free может быть недоступен (R-06, NFR-REL-04); график и задания не должны зависеть от него.

## Решение
- Интерфейс `Repository` (`ARCHITECTURE.md` §5.4, расширен в `API_CONTRACTS.md`) — единственная точка доступа UI к данным пользователя.
- До M7: `LocalRepository` на IndexedDB (Dexie), схема — `DATABASE_SCHEMA.md`.
- M7: `SupabaseRepository` (Postgres + RLS, anon-ключ, `user_id = auth.uid()`). Выбор реализации — по состоянию сессии.
- Все записи имеют `id` (UUID, генерируется на клиенте) и `updatedAt` для слияния.
- Однократный импорт локальных данных при первом входе: идемпотентно по `id`, конфликт решается по `updatedAt` (правила — `DATABASE_SCHEMA.md`).
- Производные данные (статистика навыков, дневная активность) пересчитываются из попыток и не импортируются как источник истины.
- Гостевой режим (задания без входа) отложен; до M7 приложение работает локально без входа, после M7 вход обязателен для синхронизации (политика гостя — вне этого ADR).

## Рассмотренные альтернативы
| Вариант | Почему отклонён |
|---|---|
| Сразу Supabase (вынести авторизацию в начало) | Предложение OQ-18 пользователь не принял: auth в конце; ранние вехи не должны ждать создания проекта Supabase. |
| localStorage | Лимит объёма, синхронный API, нет индексов. |
| Прямой доступ к Dexie из компонентов | Переписывание всех мест при переходе на Supabase. |
| PouchDB/CouchDB-синхронизация | Лишняя инфраструктура вне бесплатных тарифов. |

## Последствия
- Плюс: M3-M6 работают без бэкенда; тестируются на `fake-indexeddb`.
- Плюс: переход на Supabase — замена реализации и один импорт.
- Минус: до M7 данные живут в одном браузере; очистка данных сайта их теряет (нужна экспортируемая копия — Открытый вопрос).
- Минус: два набора схем (Dexie и SQL) нужно держать согласованными; общие zod-схемы в `@tl/core`.
- Минус: слияние «последняя запись побеждает» может потерять правки при одновременной работе на двух устройствах (терминальная разметка).

## Открытые вопросы
- Ручной экспорт/импорт JSON до M7 (страховка от потери IndexedDB).
- Очередь отложенной записи при недоступном Supabase (NFR-REL-04).
- Поведение, если на устройстве вошёл другой пользователь: импорт локальных данных только в первый аккаунт.
