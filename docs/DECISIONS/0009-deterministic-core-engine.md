# ADR-0009: Детерминированное общее ядро @tl/core; разборы по шаблонам; ИИ позже

Статус: принято (2026-11-03). Источник: `ARCHITECTURE.md` C7, §4.3; `PRD.md` принцип 1, FR-FB-01..03, FR-FB-08, NFR-TEST-*.

## Контекст
- Правильность ответа должна быть объективной и воспроизводимой; SMC-определения частично субъективны (R-05).
- Оценку выполняют и браузер (терминал «Проверить мою разметку»), и сервер (`grade`).
- Старые результаты должны оставаться объяснимыми после изменения правил.

## Решение
- Единый пакет `packages/core`: чистый TypeScript без DOM/Node API и без случайности (`seed` передаётся явно; `Date.now`/`Math.random` запрещены линтером).
- Публичные функции (`ARCHITECTURE.md` §4.3): `detectSwings`, `analyzeStructure`, `detectPatterns`, `findLevels`, `gradeMarks`, `resolveTrade`, `buildFeedback`, плюс `normalize`, `sliceAt`.
- `ALGO_VERSION` (semver-строка) хранится в каждой попытке и в токене задания. Любое изменение результата алгоритма повышает версию.
- Точные параметры (N фрактала, допуски, правила OB/FVG/sweep, internal/external, формула качества Challenge) — `docs/specs/ALGORITHMS.md` до начала реализации (M2).
- Разборы: `buildFeedback(gradeResult)` строит структуру из шести частей по кодам ошибок и шаблонам `apps/web/src/i18n/ru/feedback/*`; никакой свободной генерации текста.
- ИИ («Спросить ИИ», v2): отдельная кнопка, получает только проверенные алгоритмом факты (`GradeResult`, коды ошибок); вердикт ИИ не влияет на оценку.
- Тесты: Vitest, TDD; фикстуры — реальные свечи из data.binance.vision; golden-тесты на размеченных вручную участках; тест детерминизма (повторный вызов даёт идентичный результат).

## Рассмотренные альтернативы
| Вариант | Почему отклонён |
|---|---|
| ИИ (LLM) как судья | Недетерминирован, может ошибаться в «верно/неверно», стоимость и ключи; противоречит принципу 1. |
| Отдельные реализации для клиента и сервера | Расхождение оценок. |
| Эталон, размеченный вручную для каждого сценария | Не масштабируется на автогенерацию заданий (FR-TC-21). |
| Библиотека готовых индикаторов/SMC-пакет | Правила неочевидны и не версионируются нами; нельзя объяснить каждое решение пользователю. |

## Последствия
- Плюс: одна истина для UI и API; воспроизводимость; тестируемость.
- Плюс: коды ошибок связывают алгоритм, разбор и статистику навыков (FR-FB-07).
- Минус: качество разборов ограничено набором шаблонов; новые типы ошибок требуют кода + шаблона + теста.
- Минус: изменение правил обесценивает сравнение старой и новой статистики; `algoVersion` позволяет фильтровать, но не пересчитывать автоматически.
- Минус: `ALGORITHMS.md` — блокирующая зависимость для M2.
