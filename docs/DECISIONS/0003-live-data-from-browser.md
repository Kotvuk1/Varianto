# ADR-0003: Живые данные грузит браузер напрямую (REST + WS), fallback — REST-polling

Статус: принято (2026-11-03). Подлежит проверке прототипом на M0 (OQ-01). Источник: `ARCHITECTURE.md` C1, §5.1; `PRD.md` FR-DATA-01/02, R-01, R-02.

## Контекст
- `fapi.binance.com` отвечает 451, `fstream.binance.com` — таймаут из облака разработки (проверено curl, `PROJECT_STATUS.md`); серверы Vercel в США вероятно блокируются так же.
- С устройства пользователя Binance доступен (проверено пользователем), CORS `*`.
- Нужны живые свечи в терминале, включая незакрытую (FR-DATA-07).
- API-ключи не нужны и не используются (FR-DATA-16).

## Решение
- Терминал (`LiveFeed`, `apps/web/src/data/`) обращается к Binance USDⓈ-M из браузера:
  1. REST `GET https://fapi.binance.com/fapi/v1/klines` (limit до 1500) — начальная загрузка и догрузка истории влево пачками (`endTime`).
  2. WebSocket `wss://fstream.binance.com/stream?streams=<symbol>@kline_<interval>` — обновление последней свечи; `k.x === true` означает закрытую свечу.
  3. Переподключение с экспоненциальной задержкой; после переподключения REST-догрузка с последнего `openTime` закрывает пропуски.
  4. Fallback: если WS не подключился за N секунд (N фиксируется на M0), опрос REST раз в 2-5 с и индикатор «режим опроса».
  5. Ошибки 451/сети/CORS/лимита — понятное сообщение с кнопкой повтора; данные не подставляются (FR-DATA-17, NFR-REL-03).
- Все ответы проходят единый `normalize` (`@tl/core`): сортировка, дедупликация, детект пропусков, `source: 'binance-live'`.
- Сервер Binance не вызывает никогда. CSP: `connect-src 'self' https://fapi.binance.com wss://fstream.binance.com https://*.supabase.co`.
- Точные форматы сообщений — `docs/API_CONTRACTS.md`, раздел «Внешние API».

## Рассмотренные альтернативы
| Вариант | Почему отклонён |
|---|---|
| Прокси через Vercel Functions | Серверы блокируются (451); нарушает FR-DATA-01. |
| Свой VPS с ретрансляцией | Выходит за бесплатные тарифы (C5); откладывается на v2 при необходимости. |
| Сторонние агрегаторы (CoinGecko, CryptoCompare) | Другие цены и свечи, не совпадают с Binance 1:1; нарушают принцип «только Binance USDⓈ-M». |
| Только REST-polling | Допустим как fallback, но основной режим должен давать обновление незакрытой свечи без задержки и лишней нагрузки на лимиты. |

## Последствия
- Живые данные недоступны, если Binance заблокирован в сети пользователя; продукт сообщает об этом, терминал не работает, задания (ADR-0004) продолжают работать.
- Лимиты Binance (вес запросов на IP, число WS-подписок) расходуются с IP пользователя; кэширование ответов и один WS на экран. Конкретные веса и лимиты проверить на M0.
- Проверка на реальном телефоне (REST, WS, CORS, фоновая вкладка) обязательна на M0 до основной разработки.
- Живые данные не используются для заданий: их результат нельзя проверить сервером (см. ADR-0005).
