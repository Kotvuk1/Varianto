# ADR-0006: Синхронизация таймфреймов — нативные ТФ, инвариант агрегации, sliceAt

Статус: принято (2026-11-03). Источник: `ARCHITECTURE.md` §4.1; `PRD.md` FR-DATA-05, FR-CHART-05, FR-TC-04, FR-TC-05, OQ-07.

## Контекст
- Пользователь переключает 15m / 1h / 4h / 1d; графики должны совпадать с Binance 1:1.
- В Challenge ни один ТФ не должен содержать данных позже момента решения `T`, но старшая свеча, в которую попадает `T`, ещё не закрыта и должна показываться частично.
- Источники (архив и REST) отдают нативные свечи всех ТФ и 1m.

## Решение
1. Отображаемые ТФ берутся нативными у Binance. Агрегация нативные <- 1m не используется для показа закрытых свечей.
2. Инвариант (автотест на фикстурах): агрегация 1m -> 15m -> 1h -> 4h -> 1d совпадает с нативными свечами: `open` (первая 1m), `high` (max), `low` (min), `close` (последняя 1m) — точно; `volume`/`quoteVolume` — с допуском округления; `trades` — точная сумма. Границы свечей — UTC (`1d` открывается в 00:00 UTC, `4h` в 00/04/08/12/16/20 UTC).
3. `sliceAt(series, T)`: все свечи с `closeTime < T` + для каждого старшего ТФ частичная свеча, собранная из 1m в `[openTime, T)` с `closed=false`. Если `T` равен `openTime` старшей свечи — частичной свечи нет.
4. `T` выравнивается по сетке 15m. Следствие: последняя закрытая 15m-свеча заканчивается ровно перед `T`; её `close` равен `close` последней 1m до `T` и `close` частичной свечи любого старшего ТФ. Цена входа Challenge одна и та же на любом ТФ (ADR-0007).
5. Если в 1m-данных диапазона частичной свечи есть пропуск, сценарий отбраковывается при генерации (свечи не выдумываются).
6. Видимая область при переключении ТФ сохраняется по времени (центр и ширина в мс).
7. Свечи старшего ТФ с `closed=false` не участвуют в алгоритмах SMC/PA, кроме отображения (FR-DATA-08). Решение о том, участвует ли частичная старшая свеча в контексте Challenge (старший тренд), фиксирует `docs/specs/ALGORITHMS.md` (решено: см. п. 8).
8. Частичная старшая свеча (`closed=false`) не участвует в определении старшего тренда ни в Challenge, ни в «Контексте» (`docs/specs/ALGORITHMS.md` §1.1, §19 п.8).

## Рассмотренные альтернативы
| Вариант | Почему отклонён |
|---|---|
| Строить все ТФ из 1m на клиенте | Расхождение с биржей возможно из-за пропусков 1m; на длинных диапазонах большой объём данных. |
| Показывать только закрытые свечи старших ТФ | Скрывает текущий контекст, который трейдер видит в реальности; противоречит FR-TC-05. |
| Показывать полную старшую свечу, затирая будущее визуально | Раскрывает high/low/close будущего. |

## Последствия
- Для каждого ТФ в задании нужны нативные ряды и 1m за диапазон частичных свечей (до 1 суток на 1d).
- Инвариант служит регрессионным тестом ArchiveSource и нормализации.
- Все расчёты Challenge привязаны к 15m-сетке `T`; генерация выбирает `T` только на ней.
