# ADR-0001: Next.js 16 + TypeScript strict, pnpm monorepo, Vercel

Статус: принято (2026-11-03). Источник: `docs/ARCHITECTURE.md` §3, §10.

## Контекст
- Один разработчик/владелец, проверка с телефона через превью (PRD §9, R-09).
- Только бесплатные тарифы (C5): Vercel Hobby, Supabase Free.
- Нужен один язык для UI, серверных route handlers и общего ядра алгоритмов (C7): чистый TS-код `@tl/core` исполняется и в браузере, и на сервере.
- Серверная часть невелика: чтение архива Binance, подпись токенов заданий, проверка ответов (ADR-0004, ADR-0005).
- Серверы Vercel в США не видят `fapi`/`fstream` (451/таймаут, C1), поэтому серверу не нужны живые данные Binance.

## Решение
- Next.js 16 (App Router), TypeScript в режиме `strict`, React. API — route handlers (`app/api/*`, Node runtime).
- Монорепозиторий на pnpm workspaces: `apps/web`, `packages/core`, `packages/market-data`, `fixtures/`, `e2e/` (структура — `ARCHITECTURE.md` §3).
- `packages/core` не использует DOM и Node API; `packages/market-data` разделяет браузерную часть (REST/WS) и серверную (`ArchiveSource`) по entry points.
- Хостинг: Vercel Hobby; превью на каждый PR, production из `main`. До подключения Vercel проверка через `next build`, тесты и скриншоты Playwright.
- CI: GitHub Actions — lint, typecheck, unit, build, e2e.
- Валидация входов API — `zod`; общие типы контрактов живут в `@tl/core` и импортируются и клиентом, и route handlers.

## Рассмотренные альтернативы
| Вариант | Почему отклонён |
|---|---|
| Vite SPA + отдельный backend | Два деплоя и два набора конфигураций для одного разработчика; нужен ещё хостинг backend на бесплатном тарифе; нет готовых превью «фронт+API» на PR. |
| Python backend (FastAPI и др.) | Логика SMC/PA должна исполняться и в браузере (разметка, мгновенные проверки в терминале), и на сервере; два языка означали бы две реализации алгоритмов и риск расхождения оценок (нарушает принцип «единое ядро»). |
| Next.js без монорепозитория | Нельзя жёстко изолировать `core` от DOM/Node, сложнее владение зонами (Technical Analyst / Market Data / Chart). |

## Последствия
- Плюс: один язык, общие типы, превью на каждый PR, нулевая стоимость.
- Плюс: границы пакетов проверяются линтером (запрет импортов DOM/Node в `core`).
- Минус: лимиты Hobby (время и память функции, объём ответа) ограничивают серверную работу; тяжёлые операции (aggTrades drill-down, ADR-0007) требуют потоковой обработки. Конкретные лимиты проверить на M0.
- Минус: привязка к Vercel для CDN-кэширования истории (ADR-0004); переезд потребует замены кэш-слоя.
- Версия Next.js фиксируется в `package.json` точной версией; обновления — отдельными PR.
